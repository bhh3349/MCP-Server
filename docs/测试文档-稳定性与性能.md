# MCP-Server 稳定性与性能测试文档

版本：v0.1.1 | 日期：2026-10-05

## 一、测试目标

验证 MCP-Server 在真实使用规模（5-6 个信道）下的长期稳定性，找出性能瓶颈和异常恢复能力。

## 二、测试环境

| 项目 | 要求 |
|------|------|
| 服务器 | 2核4G 以上，Ubuntu 20.04+ / Windows 10+ |
| Node.js | v18+ |
| 网络 | 公网可访问（网关模式）或局域网（本地信道） |
| 测试时长 | 稳定性 ≥ 24h，性能 ≥ 1h |

### 部署步骤

```bash
# 1. 拉取代码
git clone https://github.com/bhh3349/MCP-Server.git
cd MCP-Server

# 2. 安装依赖
npm install

# 3. 构建
npm run build

# 4. 启动（带 dashboard）
node dist/local/cli.js --dashboard
```

## 三、稳定性测试

### 3.1 长跑测试（24h）

**目标**：无人工干预连续运行 24 小时

**步骤**：
1. 启动服务，记录起始时间、内存占用
2. 保持 5-6 个信道连接（可用多个 AI 客户端或脚本模拟）
3. 每小时记录一次：
- 进程内存（`ps aux | grep node` 或任务管理器）
- 信道连接数
- dashboard 是否可访问
- 错误日志条数

**通过标准**：
- [] 24h 无崩溃、无需重启
- [] 内存增长 < 200MB（无明显泄漏）
- [] 信道无异常断开（或断开后自动重连）

### 3.2 异常恢复测试

| 场景 | 操作 | 预期 |
|------|------|------|
| 网络闪断 | 断开网络 30s 后恢复 | 信道自动重连 |
| 服务重启 | kill 进程后重启 | dashboard 数据恢复 |
| 磁盘满 | 填满磁盘后清理 | 优雅降级，不崩溃 |
| 高负载 | CPU 打满 5 分钟 | 响应变慢但不丢请求 |

### 3.3 内存泄漏检测

```bash
# 每小时采样
ps -o pid,rss,etime -p <PID>

# 或用 Node 内置
node --expose-gc dist/local/cli.js --dashboard
# 在 dashboard 日志页观察内存曲线
```

**判定**：RSS 持续单调增长且 GC 后不回落 → 泄漏

## 附录：压测脚本

```python
# stress.py - 简单并发压测
import asyncio, aiohttp, time, statistics

URL = "http://127.0.0.1:18789/mcp/<token>"
CONCURRENT = 6
TOTAL = 1000

async def call_tool(session):
payload = {
"jsonrpc": "2.0", "id": 1,
"method": "tools/call",
"params": {"name": "server_info", "arguments": {}}
}
start = time.time()
async with session.post(URL, json=payload) as r:
await r.json()
return (time.time() - start) * 1000

async def main():
latencies = []
async with aiohttp.ClientSession() as s:
for i in range(0, TOTAL, CONCURRENT):
batch = [call_tool(s) for _ in range(CONCURRENT)]
latencies.extend(await asyncio.gather(*batch))
if i % 100 == 0:
print(f"进度: {i}/{TOTAL}")
latencies.sort()
print(f"p50: {latencies[len(latencies)//2]:.1f}ms")
print(f"p95: {latencies[int(len(latencies)*0.95)]:.1f}ms")
print(f"p99: {latencies[int(len(latencies)*0.99)]:.1f}ms")

asyncio.run(main())
```
